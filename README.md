# RoutineAI

스마트폰 사용 로그에서 **무의식적 반복을 발견해, 패턴이 일어나는 그 순간에
루틴으로 제안**하는 개인용 안드로이드 앱. 수락·거절의 맥락을 다시 학습해
쓸수록 조건이 정교해진다.

> 한 줄 요약: 발견은 기계가, 확인은 사람이. 거절도 연료다.

## 전체 흐름

```
수집 ──→ 집계 리포트 ──→ 1차 해석(LLM) ──→ 구조화 제안
                                             │
   ┌─────────────────────────────────────────┘
   ▼
그 순간의 팝업 (가장자리 발광 → 카드) ──→ 사용자의 원탭 결정
   │                                        │  (수락·보류·무시가 8축 맥락과 함께 기록)
   ▼                                        ▼
실제 적용 (앱 실행·모드 변경)          심층 분석 에이전트 (tool calling)
                                            │  조건 정제 · 실험(만료·자동 롤백) · 메모리
                                            ▼
                                   나우 브리프 카드 ←→ 원탭 응답 (다시 기록으로)
```

## 받은 사람을 위한 읽기 순서

이 저장소를 처음 파악한다면 (사람이든 에이전트든) 이 순서를 권한다:

1. **이 README** — 구조와 원칙.
2. **`git log`** — 커밋 메시지가 곧 결정 기록이다. "왜 이렇게 했는가"와
   실측으로 확정한 사실(삼성이 분할 토글을 거부한다 등)이 전부 거기 있다.
3. **`app/src/main/assets/skill/SKILL.md`** — 해석의 철학. 통계가 문을 열고
   서사가 통과시킨다.
4. **`watch/PatternWatcher.kt`** — 발화 규칙의 전부 (단일 신호 관문, 억제
   장치, 보류 중 기능의 복원 지점).
5. **`interpret/DeepAnalyzer.kt` + `assets/skill/deep-analysis.md`** —
   도구를 쥔 개선 에이전트.
6. **`docs/EXTENSIONS.md`** — 구현하지 않기로 한 것들의 설계 기록.

## 설계 원칙

**계산과 해석을 분리한다.** 앱은 집계만 한다 — `Report` 에 해석 문장이 한
줄도 없다. 의미("장 마감이라 거절했다")는 세계지식이 필요하므로 LLM 의
몫이고, 경계를 앱이 그으면 모든 사용자에게 같은 경계가 강요된다.

**같은 신호도 사람마다 뜻이 다르다.** 그래서 "외출" 같은 맥락을 기능으로
정의하지 않는다. 조건부 비율(기울기)은 개인 기준선 대비라, 늘 셀룰러인
사람에겐 셀룰러 축이 저절로 무의미해진다 — 개인화가 규칙이 아니라 수학에서
나온다.

**모든 실행은 사용자의 탭이다.** 자동 실행은 보류 중이고, 에이전트의 변경
권한은 만료·자동 롤백이 있는 실험뿐이다. 조건을 바꾸면 근거 문장(insight)이
화면에 남는다.

**휘발은 스냅샷, 재구성 가능한 것은 조인.** 결정 순간의 기기 상태(소리
모드·충전·연결 기기)는 그 자리에서 스냅샷하고, 전후 타임라인은 원본 로그를
분석 시점에 조인한다(`get_moment_context` 도구).

**정직한 실패.** 적용 결과의 `real` 플래그가 "실제로 했는지, 안내만
했는지"를 구분한다. 삼성이 막는 것(분할 토글·루틴 등록·Now Brief)은 막혀
있다고 화면에 그대로 말한다.

## 구조

코드 경로는 `app/src/main/java/com/routineai/` 하위의 축약 표기다.

```
data/       Room v9 — 원본 로그 · 제안 · 결정 이력(proposal_event, 8축 맥락) · 실험
collect/    UsageStats · NetworkStats · 알림 리스너 · BT 리시버 · Health Connect · 6시간 워커
analysis/   Sessionizer(계측 함정) → Analyzer(집계·조건부 비율·nightHabit) → Report
interpret/  Interpreter(Azure, tool calling 루프) · ProposalEngine(1차 제안 병합)
            DeepAnalyzer(심층 에이전트) · Experiments(만료·롤백) · Memory(개인 맥락 입구)
watch/      WatchService(1.5초 폴링 5종) → PatternWatcher(단일 관문·발화 규칙)
            → SuggestionOverlay(발광·카드) → Applier(실제 적용) · DecisionContext(스냅샷)
assets/     dashboard.html · skill/(1차 해석 지침 6개 + deep-analysis.md)
tools/      make_demo_db.py — 실기기 기록에서 데모 DB 추출 (BUILD.md 참고)
docs/       EXTENSIONS.md(확장 설계 기록) · 발표 자료(*.pptx 는 저장소 제외)
```

화면은 4탭: **대시보드**(리포트) · **제안**(후보 심사) · **루틴**(나우
브리프 + 에이전트 카드 + 수락 루틴) · **설정**(권한·수집·Azure·데모).

## 감지가 접근성 없이 도는 이유

삼성은 접근성 서비스를 재설치마다 끄고, adb 로 켜도 되돌린다. 그래서 **사용
정보 접근 권한만으로 도는 1.5초 폴링이 주 경로**다(앱 전환·BT·Wi-Fi·시각·
운동). 접근성은 있으면 더 빠른 보조일 뿐이며, 그때 앱 전환 폴링은 쉰다.
같은 사건의 중복 보고는 `PatternWatcher.signal` 관문(5초)에서 접힌다.

## 데모 모드

`assets/demo/routine.db` 가 있으면 설정 탭에서 데모 모드를 켤 수 있다 —
리포트를 실측 기반 데모 로그로 만든다. **이 파일은 실사용 기록이라 저장소에
없다**(.gitignore). 클론 빌드에서는 데모 토글이 비활성화되고, 실기기 수집
경로는 그대로 동작한다. 발표 자료(pptx)도 같은 이유로 저장소에 없다.

## 계측 함정 처리

집계에서 다음을 처리한다. 빼면 통계가 **조용히** 틀린다.

| 함정 | 처리 | 위치 |
|---|---|---|
| 화면 꺼진 뒤 마지막 앱에 시간이 계속 쌓임 | 화면 ON 구간으로만 집계 + 1시간 상한 | `Sessionizer` |
| 같은 초에 두 앱 동시 실행을 전환으로 오인 | 분할화면으로 분류, 전환에서 제외 | `Sessionizer` |
| 화면·잠금 이벤트의 프로필별 중복 | (종류, 초)로 중복 제거 | `Sessionizer` |
| 첫날·마지막날 부분 기록 | 커버리지 검사 후 평균에서 제외 | `Analyzer` |
| net 버킷이 fg/bg/tag 로 쪼개져 옴 | 합산 후 저장값과 max 병합 | `NetworkCollector` |
| 단순 횟수가 사용 빈도에 오염됨 | 조건부 비율(기울기)로 판정 | `Chains` |
| 앱 시간 합계 ≠ 화면 시간 | 검산해 `Quality.reconciliationDelta` 노출 | `Analyzer` |

## 실측으로 확정한 플랫폼 한계

- **분할화면 토글**: 접근성 전역 동작을 One UI 가 거부한다
  (a11y=true·widthDp=874·toggled=false). 앱페어는 순차 실행으로 낙하.
- **삼성 루틴 등록**: .routine 파일은 본문 암호화 + 비밀 키 HMAC — 서드파티
  등록 경로 없음. 그래서 이 앱이 자동화 엔진 역할을 직접 한다.
- **Now Brief**: 콘텐츠 연동 API 없음 — 루틴 탭의 브리프가 자체 표면이다.
- **삼성 헬스 → Health Connect**: 연동 후 새 데이터부터만 동기화(소급 없음).
- 과거 Wi-Fi 이력·배터리 히스토리는 시스템이 앱에 주지 않는다. BT·장소는
  설치 시점부터 직접 기록한다.

## 빌드·실행

> `gradlew` 래퍼 스크립트는 저장소에 없다 — Android Studio 로 열어 Sync
> 하거나 `gradle wrapper --gradle-version 8.11.1` 로 먼저 생성한다 (상세:
> `BUILD.md`).

```bash
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`minSdk 29` · `compileSdk 36` · Kotlin 2.0 / Compose · AGP 8.9.

해석 기능은 설정 탭에 Azure OpenAI 4개 값(엔드포인트·키·API 버전·배포
이름)을 넣으면 켜진다. **tool calling 을 지원하는 배포**여야 심층 분석
에이전트(도구·실험·메모리)가 온전히 동작한다 — 미지원 배포면 도구 없는
한 방 호출로 조용히 낙하해 1차 해석과 기본 정제만 된다.

## 개인정보

- 알림 **본문은 읽지도 저장하지도 않는다.** 발신 앱·채널·시각·방해 여부만.
- Wi-Fi 이름은 로컬 DB에만 있고, 리포트에는 `Wi-Fi A` 별칭으로만 나간다.
- 1차 해석에 전송되는 것은 집계 수치뿐이다. **심층 분석은 예외가 있다**:
  에이전트가 `get_moment_context` 도구로 특정 결정 순간 ±수 분의 원본 로그
  조각(앱 전환·알림 발신 앱·BT 기기명)을 조회하면 그 조각이 LLM 에 전송된다
  — 전체 로그가 아니라 에이전트가 지목한 순간의 창 하나이며, 심층 분석을
  쓰지 않으면 일어나지 않는다.
- 개인 맥락 메모리는 `files/memory.md` 로컬 파일이다 (없어도 동작).
- 백업 제외(`allowBackup=false`).
