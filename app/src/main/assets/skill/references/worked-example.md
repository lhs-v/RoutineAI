# 절차 시연 — 세 후보가 어떻게 갈리는가

판단 과정을 보기 위한 예시다. 수치는 예시일 뿐 다른 데이터에 적용하지 않는다.
셋 다 3단계(통계 문턱)는 통과했다 — 갈림은 전부 4·5단계에서 일어난다.

## 사례 1 — 통과: 증권 앱 페어

**통계**: appPairs — A(금융 슈퍼앱)↔B(증권사 앱) 왕복 37회 · 중앙 간격 2초 ·
홈 경유 16% · coUseCount 24(5일).

**목적성**: A 는 결제·송금에 주식 커뮤니티가 활발한 앱. B 는 거래·시세 앱.

**서사**: "커뮤니티의 종목 반응 확인 ↔ 거래·시세 확인을 한 활동으로 오간다."

**검증**: 간격 2초 — 사람이 목적을 바꾸기엔 짧고, 오가며 두 화면을 겹쳐 보는
동작과 맞다. 홈 경유 16% — 한 흐름. 분할화면 24회 실측(C2) — 서사가 이미
행동으로 나타났다. 장중 시간대 쏠림(C8)이 배경을 지지.

**제안**: app_pair · confidence 확인됨. oneLine "A와 B를 분할화면 앱페어로
묶을까요?" — 이미 하고 있는 행동의 마찰만 없애는 제안이다.

## 사례 2 — 기각: 왕복 1등이지만 서사가 없다

**통계**: appPairs — C(AI 챗)↔D(브라우저) 왕복 56회로 **최다** · 중앙 간격
31~38초 · 홈 경유 70%.

**목적성**: 둘 다 범용 도구라 목적이 특정되지 않는다.

**서사 시도**: "챗의 답을 브라우저에서 검증한다"? — 간격 31초는 이어지는 확인
동작치고 길고, 홈 경유 70%는 매번 흐름을 끊고 나간다는 뜻이다. "독립 작업의
병행" 서사가 더 그럴듯하다(C3 반박).

**처리**: rejected — "왕복 56회로 최다지만 간격 31~38초·홈 경유 70%로 하나의
작업 서사가 서지 않음. 병행 사용으로 보임." **횟수 1등이 기각되는 것이 이
절차의 존재 이유다.** (앱페어 자체는 병행에도 편리할 수 있으나, 근거가 "습관의
발견"이 아니게 되므로 이 시스템의 제안으로는 내지 않는다.)

## 사례 3 — 통과: 이어폰 → 음악

**통계**: eventChains — BT연결:버즈 → 음악 앱 9회 · 7일 · 중앙 gap 17초.
appContext — 음악 앱 실행의 73%가 버즈 연결 중 (영상 앱 41%, 배경 앱들 20%대).

**목적성**: 이어버즈 착용은 듣기의 시작 신호다.

**서사**: "이어폰을 끼는 것이 음악 감상 시작의 의식이다."

**검증**: gap 17초 — 착용 후 폰을 꺼내 잠금 해제하는 시간과 맞다. 조건부 비율의
기울기(73>41>20%)가 이 앱만의 패턴임을 지지(C1). 반복 7일.

**제안**: trigger_routine · confidence 확인됨(BT 커버리지가 짧으면 유력으로).
oneLine "버즈를 연결하면 음악 앱을 바로 열까요?" — samsungCondition
specify_bluetooth_v3, samsungAction launch_app_v3.

## 요약 — 반복해서 작동한 판단

1. 문턱은 기계적으로, 판정은 서사로. 순서를 바꾸면 둘 다 망가진다.
2. 간격·홈경유·방향비는 서사의 거짓말 탐지기다.
3. 분할화면·조건부 비율 기울기 같은 **행동 실측**이 최고의 지지 증거다.
4. 기각 사유는 서사로 쓴다 — 그 자체가 사용자에게 좋은 정보다.
