# 품질 확인 — 앱이 처리한 것과 여전히 의심할 것

계측 함정의 대부분은 리포트를 만드는 앱이 코드로 처리했다. 당신이 원본 이벤트를
볼 수 없으므로 "탐지하라"는 지시는 의미가 없다 — 대신 **처리 결과를 검산 필드로
확인**하고, 앱이 처리할 수 없는 함정만 직접 의심한다.

## 앱이 이미 처리한 것 — 필드로 확인만 한다

| 함정 | 앱의 처리 | 확인할 필드 |
|---|---|---|
| 시간대 변환 오류 | 전 구간 기기 표준시로 계산 | `meta.tz` |
| 화면 꺼진 뒤 앱에 시간 누적 | 화면 ON 구간으로만 집계 + 1시간 상한 | `quality.reconciliationDelta` — **음수면 앱 지표 기반 제안 전부 보류** |
| 같은 초 동시 실행을 전환으로 오인 | 전환에서 제외, `coUse` 로 분리 | `quality.coUseEventsExcluded` |
| 프로필별 중복 기록 | (종류, 초) 중복 제거 | `quality.duplicateEventsDropped` |
| 부분 기록된 첫날·마지막날 | 평균에서 제외 | `meta.partialDays` |
| 관측 창 불일치 | 모든 소스를 사용 이벤트 시작점으로 통일 | `meta.spanFrom` |
| 알림 재게시(미디어 갱신) | (앱, 채널) 5초 창으로 접음 | `diagnostics.notifRepostsCollapsed` |
| 기록 없음 vs 값 0 | 커버리지 플래그로 구분 | `days[].notifCovered`, `diagnostics.notifListenerSince` |

`quality.warnings` 는 앱이 남긴 자연어 경고다. 반드시 analysisNote 에 반영한다.

## 여전히 직접 의심할 것

**S1. 백그라운드를 사용자 행동으로 오인** — `netApps` 는 통신량이지 사용이 아니다.
화면 꺼진 동안의 트래픽이 섞여 있다. 모바일 비율은 "밖에서 쓰는 앱"의 신호로만.

**S2. 한 기기, 여러 사용자** — 특정 구간만 앱 조합·시간대가 평소와 다르면
그 구간 기반 제안의 confidence 를 낮추고 narrative 에 가능성을 남긴다.

**S3. 앱의 자동 동작** — 실행 횟수는 "화면에 다시 나타남"을 세는 정의라
(`launchesPerDay`), 앱 내 화면 전환·자동 복귀도 는다. 절대값보다 앱 간 비교와
추세로 쓴다.

**S4. 관측 창이 특수한 기간** — 연휴·기기 교체 직후·앱 설치 직후는 평소가 아니다.
`meta` 의 기간과 요일 구성(`quality.weekdayCount/weekendCount`)으로 감을 잡는다.

**S5. 짧은 커버리지의 소스** — BT·헬스는 수집 시작이 늦을 수 있다.
해당 소스만으로 만든 제안은 confidence 상한을 "유력"으로 둔다.
